# Recall Desk

**Permissions are scoped. Recall Desk makes enforcement scoped, too.**

A person can withdraw permission for one use without requiring indiscriminate removal everywhere. Recall Desk enforces that scoped change across a small team's tools:

- **Airtable** — rights / permission registry (what the organization is allowed to do)
- **Notion** — published / live content
- **Trello** — planned editorial content

The model investigates meaning. Code identifies the exact registered assets, decides the permitted actions, journals writes, and verifies outcomes. **UNCERTAIN never authorizes content mutation.**

## Demo: Amara's request

Amara asks Riverbend Youth Makerspace to **stop using her photo for volunteer recruitment**, and to **keep the 2024 Spring Workshop Recap**.

Expected result for the main live run:

| Count | N |
| --- | --- |
| Removed | 1 |
| Held | 1 |
| Preserved | 2 |
| Uncertain | 1 |
| Manual | 1 |
| Failed | 0 |

**Final result: `NEEDS_FOLLOW_UP`**

That is not a failed run. One planned post is undecided, and one printed flyer is outside connected systems. Code computes the final result; the model cannot override it.

## How it works

**The model interprets; code enforces.**

| Phase | Who | What |
| --- | --- | --- |
| 0 | Code | Load the request, asset, variants, and registry from Airtable. A failed read is `FAILED_SAFE`. |
| 1 | Model + person | Interpret scope. A person approves the scope once, not individual clicks. |
| 2 | Code | Discover occurrences by **exact** registered identifiers. |
| 3 | Model | Investigate each candidate with read-only tools. Output `REMOVE`, `PRESERVE`, or `UNCERTAIN`. |
| 4 | Code | Validate evidence. Rules only move decisions toward `UNCERTAIN`. |
| 5 | Code | Map verdicts to allowed actions. Content writes target validated `REMOVE` only. |
| 6 | Code | Journal `SENT` before each external write; execute; reconcile unknown outcomes by reading. |
| 7 | Model + code | At most one re-evaluation after drift. |
| 8 | Code | Independent verification, registry sync, computed final result. |

Bounded autonomy:

- the model investigates meaning
- code identifies exact registered assets
- deterministic policy decides permitted actions
- a durable journal records writes
- verification reconciles outcomes
- `UNCERTAIN` never authorizes content mutation

## Reliability claims

These are the properties the runtime is built to keep. Measured numbers, when frozen, live in `eval/report.md` and are generated by the eval writer — never edited by hand.

| Claim | How it is enforced |
| --- | --- |
| Exact identifier matching only | Canonical URL, or a filename that maps to exactly one variant. No face match, perceptual hash, or fuzzy match. [`src/recall_desk/discovery.py`](src/recall_desk/discovery.py) |
| No content mutation outside validated REMOVE | Plan validator plus executor. [`src/recall_desk/policy.py`](src/recall_desk/policy.py) |
| `SENT` is durable before the HTTP write | Journal transition, then the port call. [`src/recall_desk/executor.py`](src/recall_desk/executor.py), [`src/recall_desk/journal.py`](src/recall_desk/journal.py) |
| Unknown outcomes are reconciled by reading | No blind retry of an unknown write. See [`CONTRACT.md`](CONTRACT.md) |
| Trello hold is composite and idempotent | Move + label + same-request marker. Partial holds are not rolled back. Reruns with the same-request marker do not duplicate the hold. |
| `UNCERTAIN` is fail-safe | No Notion archive, no Trello hold. Manual follow-up with the missing or conflicting evidence. |
| Coverage is the connected systems plus the registry | Anything else, including the printed flyer, is `Manual`. |
| Final result is computed by code | [`src/recall_desk/status.py`](src/recall_desk/status.py) |

Longer write-up: [`SYSTEM_RELIABILITY.md`](SYSTEM_RELIABILITY.md).

## Eval report

`recall_desk.evals.report.write_report` writes `eval/report.md` and `eval/results.json` from measured inputs (UTC time, commit, model id, `Frozen: yes|no`, gate, and the exact metric lines).

Do not invent or hand-edit those numbers. If `eval/report.md` is not in the repo yet, the reliability lane has not frozen results.

## What we don't claim

- **No legal judgments.** A person approves the permission scope; the agent investigates connected occurrences and determines whether each one falls within that approved scope. It does not make legal or policy decisions.
- **No guessing.** When the evidence doesn't clearly decide a use, Recall Desk changes nothing and asks a person. A planned UNCERTAIN item could still go live if nobody reviews it, so the report shows its scheduled date.
- **"Removed" means the image block is archived on the Notion page.** An admin can restore it. We make no claims about caches, screenshots or emails already sent.
- **"Held" means the Trello card is moved aside and the restriction is recorded in Airtable.** It flags the card in the team's workflow; it doesn't stop anyone from publishing.
- **Coverage means the connected systems plus the registry.** Everything else is listed as manual follow-up.
- **Only uses of the image count.** Mentions of the person's name in text are out of scope.

## Run it

### Live demo (keys required)

From the repo root, with Notion, Trello, Airtable, and Anthropic credentials in the environment:

```powershell
python -m recall_desk.cli reset
python -m recall_desk.cli check-fixtures
python -m recall_desk.cli run REQ-001 --approve
```

Expected on a clean fixture reset: `Final result: NEEDS_FOLLOW_UP`, counts `Removed=1`, `Held=1`, `Preserved=2`, `Uncertain=1`, `Manual=1`, `Failed=0`. The run report is written to `runs/{run_id}.md`.

Timed voiceover and on-screen beats: [`DEMO.md`](DEMO.md).

### Sim / tests (no keys)

```powershell
python -m pip install -e ".[dev]"
python -m pytest -q
```

Default pytest excludes `full` marker suites.
